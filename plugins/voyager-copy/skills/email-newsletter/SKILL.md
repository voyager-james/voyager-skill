# Email and Newsletter Copy

Interview first, then write. Never draft before the summary is confirmed.

## Workflow

1. **Collect context.** Follow protocol section 1. Pull the offer, list, voice and proof from what is already known.
2. **Round 1.** Ask the questions in `references/interview.md`, skipping any already answered.
3. **Round 2.** Ask only the follow-ups the Round 1 answers trigger.
4. **Readiness gate and summary.** Check the required fields, post the confirmation summary and wait for a yes.
5. **Route the answers** using the table below, then write.
6. **Quality gate.** Email checklist, then the human-voice lint.
7. **Deliver** the copy, then assumptions and next-step offers.

## How answers change the copy

| Answer | What it changes |
|---|---|
| Type: newsletter | Value first. One main insight, optional quick hits, one CTA. Recurring voice, not a hard sell. |
| Type: promo broadcast | Offer, reason to act and proof up front. Single CTA repeated 2 to 3 times. |
| Type: welcome sequence | Email 1 delivers what was promised and sets expectations. Later emails build trust before any ask. |
| Type: nurture sequence | Each email teaches one thing and moves the reader one step. Ask lightly. |
| Type: launch or webinar sequence | Announce, teach, prove, remind, close. Real deadlines only. |
| Type: re-engagement | Short, human, low pressure. Give an easy way to say yes or to leave. |
| Goal: educate | Story or problem, insight, takeaway. Soft CTA (reply, read, watch). |
| Goal: drive a click | One link, one reason to click, curiosity plus relevance. |
| Goal: book a call | Frame the call as a fit check with a clear outcome. |
| Goal: sell | Name the offer, price where relevant, objection handling and proof. |
| Goal: reactivate | Acknowledge the silence, lead with a fresh reason to come back. |
| Cold or new list | Build trust, lower the ask, more explanation of who you are. |
| Warm or customer list | Skip the introductions, reference the relationship, more direct ask. |
| Length: short, standard, long | See the length bands in `references/email-rules.md`. |

## Deliverable format

Single email:

```
Subject: <30 to 50 characters>
Preview: <completes or expands the subject>

<body>

<CTA line>

<Sign-off>

P.S. <reinforcement or secondary benefit>
```

Sequence: a one-line map first (email number, day, purpose, CTA), then each email in the format above.

Offer 2 alternative subject lines for the most important email. Use `{{first_name}}` style merge tags only if the user names their platform's syntax, otherwise write "Hey [First name],".

## Final review checklist

- [ ] Subject is 30 to 50 characters and honest about the content
- [ ] Preview text extends the subject and does not repeat it
- [ ] Opening line uses "you" language and gets to the point
- [ ] Body follows a story or problem, insight, solution, CTA arc
- [ ] One primary CTA (may repeat 2 to 3 times), no competing links
- [ ] Length matches the chosen band
- [ ] No fake urgency or scarcity
- [ ] Reads like one person writing to one person
- [ ] Human-voice lint exit code 0
