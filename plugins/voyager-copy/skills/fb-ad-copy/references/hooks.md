# Hook Engineering (video ads and hook requests)

If the hook fails, the ad fails. Build hooks before the body of a video ad.

## Rules

1. Hook-first: build hooks before writing the rest of the ad.
2. Always output a batch, never one hook.
3. Assume mobile and sound off. Short, visual, readable without audio.
4. Every hook has attention capture (callout, pattern interrupt or open loop) and implied value for continuing (benefit, curiosity or outcome).
5. Plain, direct language at a 6th to 8th grade reading level. It should sound like a person talking.
6. Prefer specifics: the niche, the number, the timeframe, the result.
7. Hooks are 3 to 7 seconds spoken and 12 words or fewer on screen.
8. If a claim needs proof, soften it ("might", "can", "up to") or ask for the proof asset.

## Hook formats

Use the same core idea across several formats.

| Format | Pattern |
|---|---|
| Conditions | "If you're a [audience], this will help you [result]." |
| Label or gift | "[Audience], I have something for you." |
| Open loop | "Real quick question..." |
| Rumor | "The rumors are true..." |
| Imperative | "Watch this if you want to [outcome]." |
| Contrarian | "Stop doing X if you want Y." |
| Specificity | Numbers, timeframes, named outcomes |
| Pain to relief | "If you're tired of X, do this." |
| Proof-led | "We did X and got Y." |
| Pattern interrupt | Unexpected first frame, visual-first |

## Match the hook to the tone framework

Decide the framework first, then choose the hook format that leads into it. Hook and body must share the same emotional register.

| Hook format | Natural body framework |
|---|---|
| Pattern interrupt | Pattern Interrupt |
| Conditions or label | Aspirational or Social Proof |
| Pain to relief | Challenge-Led |
| Proof-led | Social Proof |
| Contrarian | Pattern Interrupt or Challenge-Led |
| Open loop | Any framework |
| Specificity | Challenge-Led or Aspirational |

## Standard batch: 30 hooks (70/20/10)

Default to 30 unless the user asks for fewer.

- **21 safe winners (70%):** proven formats applied to new angles. With no performance data available, use the well-proven formats (conditions, pain to relief, specificity, proof-led, contrarian).
- **6 permutations (20%):** remixes of the strongest safe winners with new wording, framing or visual.
- **3 wildcards (10%):** completely new patterns.

If the user supplies performance data (thumbstop, 3-second hold, CTR, CPA), take the top 5 hooks and build the 70/20/10 batch from those patterns.

### Hook detail card (per hook)

| Field | Spec |
|---|---|
| Hook text | 12 words or fewer when possible |
| First-frame visual | What is on screen in seconds 0 to 1 |
| On-screen text | Optional, 3 to 6 words |
| Spoken line | Optional, conversational |
| Angle | pain, benefit, proof, curiosity or contrarian |
| Audience callout | Who it is for |

To keep a 30-hook batch readable, list all 30 as one line each (number, hook text, angle, format), then give the full detail card for the 5 the user is most likely to shoot.

### Quick-shoot shortlist

Add 5 hook and visual pairings that can be shot in under 30 minutes with a simple setup.

## Testing guidance (only when asked, or when performance data is given)

- A/B test hooks with every other variable held constant (script, offer, CTA).
- Launch in small batches of 5 to 10 hooks.
- Kill hooks with a low 3-second hold rate or low thumbstop.
- Scale hooks that lift early retention.
- Weak performance with a low 3-second hold rate is a hook problem. Fix the hook before the script or the offer.

| Metric | Tells you |
|---|---|
| Thumbstop rate | Did it stop the scroll? |
| 3-second view rate | Did it earn the first 3 seconds? |
| 25% and 50% view rate | Did it hold attention past the hook? |
| CTR | Did it create intent to act? |
| CPA | Did the traffic convert? |

## Missing inputs

Ask only for what is missing: audience, offer, primary pain and desired outcome, proof assets. If the user skips, make 3 reasonable assumptions, state them, and generate anyway.
